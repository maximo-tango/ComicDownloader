# Image Hunter v1.5.0 테스트 결과

- 실행일: 2026-10-29
- 환경: Linux(Codespace, CPU 2개), Node.js 24.21.0, Chrome for Testing 148.0.7778.97 (headless, Puppeteer 24)
- 결과: **단위·브라우저 테스트 93/93 통과**, **종단 간(E2E) 33/33 단계**: v1.3.0(29단계)에서 10회 중 9회 전부 통과(1회는 아래 "남은 문제" 참고), v1.5.0 변경 후 5회 중 마지막 3회 연속 전부 통과(처음 2회는 아래 "남은 문제" 참고)
- 실행하지 않은 항목은 맨 아래 "실행하지 않은 테스트"에 따로 적었습니다. 실행하지 않은 항목을 통과로 적지 않았습니다.

```bash
npm test            # 단위 85건 + 브라우저(실제 Chrome 페이지에서 수집기 실행) 8건
npm run test:e2e    # 확장 프로그램 전체를 Chrome에 로드해 33단계 실행
```

> E2E 조건: 배포용 manifest는 모든 사이트 접근(`<all_urls>`)을 기본으로 받지만, 테스트용 사본은 `http://127.0.0.1/*`만 받도록 바꿨습니다(사용자가 Chrome에서 사이트 액세스를 제한한 상태와 같음). 그래야 권한이 없을 때의 동작도 확인할 수 있습니다. 두 번째 출처 `http://localhost`는 권한 없이 두고, 권한이 없을 때의 동작을 확인했습니다. 실제 activeTab 흐름은 수동 테스트 M2입니다.

## 서비스 워커 "응답 없음"의 원인 (테스트 환경 문제로 판단)

1번과 16번 문제(다운로드 전체가 응답 없음)는 수정 후에도 E2E에서 가끔 다시 나타났습니다. 원인은 **테스트 도구(Puppeteer)가 서비스 워커에 디버거를 붙여 둔 것**으로 판단합니다.

- 디버거가 붙은 상태에서 Chrome이 워커를 다시 시작하면, 새 워커가 "디버거가 실행을 허락할 때까지 대기" 상태로 멈출 수 있습니다.
- 관찰한 증상(워커 무응답, 디버거로도 일시정지 불가, 새 워커는 빈 상태)이 모두 이 설명과 맞습니다.
- 테스트가 워커에 디버거를 붙이지 않도록 바꾸었습니다. 확장 ID는 경로로 계산하고, 탭 조회는 확장 페이지에서, 워커 재시작 테스트는 Chrome의 ServiceWorker 기능으로 합니다. 그 뒤 연속 9회 동안 한 번도 나타나지 않았습니다.
- 실제 Chrome에는 디버거가 붙어 있지 않습니다. 그래도 워커가 언제 재시작되어도 상태를 잃지 않게 한 수정(1번, 16번)은 그대로 두었습니다.

## 남은 문제

- E2E 10회 중 1회, 일괄 다운로드 16개 중 1개가 사용자 취소 없이 "취소" 상태로 끝났습니다. 이후 진단 정보를 넣고 8회 더 실행했지만 다시 나타나지 않아 원인을 확인하지 못했습니다. 다시 나타나면 테스트가 작업 상태와 Chrome 다운로드 기록을 함께 출력합니다. 실제 사용 중 이런 항목은 다운로드 화면에서 **재시도**하면 됩니다.
- v1.5.0 작업 중 E2E 5회 중 처음 2회에서, 일괄 다운로드 자체는 성공(14/14)했지만 **목록 카드의 다운로드 상태 표시가 갱신되지 않아** 그 표시를 보는 4단계([19][23]의 카드 확인, [9], [21], [24])가 실패했습니다. 두 번째 실패 이후 코드 변경 없이(테스트의 진단 메시지만 추가) 3회 연속 전부 통과했고, 직전 커밋(v1.4.1)도 같은 환경에서 1회 전부 통과했습니다. 원인은 확인하지 못했습니다. 카드 상태가 안 바뀌어 보이면 다운로드 탭에서 실제 상태를 확인할 수 있습니다.
- 실제 사이트에서 "화면 위치 순서"와 "조건 완화"를 시험하지 않았습니다. 로컬 테스트 페이지로만 확인했습니다.
