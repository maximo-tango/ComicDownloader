## 실행 방법

```bash
npm install          # Puppeteer와 Chrome for Testing 설치 (E2E용)
npm test             # 단위 테스트
npm run test:e2e     # E2E (포트 변경: E2E_PORT=8793, 스크린샷: SCREENSHOTS=폴더)
node tests/fixtures/server.mjs   # 수동 확인용 테스트 사이트 → http://localhost:8765/
```

## 테스트 중 발견해 수정한 문제

1. **스크롤 재탐색이 지연 로딩 이미지를 찾지 못함**: 분석 대상 탭이 백그라운드에 있으면 브라우저가 렌더링을 멈춰 IntersectionObserver 기반 지연 로딩이 일어나지 않았습니다. 이제 스크롤하는 동안 대상 탭을 앞으로 가져왔다가 분석 화면으로 돌아옵니다.
2. **Referer가 필요한 이미지의 다운로드 실패(403)**: Chrome의 요청 헤더 규칙은 `chrome.downloads` 요청에는 적용되지 않습니다(규칙 4가지 형태로 확인). 이제 다운로드가 거부되면 서비스 워커가 Referer를 붙여 직접 받아 저장합니다. 이때 서버 파일명도 유지됩니다.
3. **실패한 다운로드 이름이 `missing.txt.png`처럼 생성됨**: 오류 응답의 MIME 형식에서 나온 확장자를 이미지 확장자로 바꾸도록 수정했습니다.
4. **실패 목록이 `download.txt`로 저장됨**: 파일명 결정 리스너가 있으면 Chrome이 `downloads.download`의 `filename`을 무시합니다. 내보내기 파일명도 서비스 워커가 지정하도록 바꿨습니다.

## 수동 확인 권장 항목 (자동화하지 않음)

- Windows 11 + 일반 Chrome에서 설치 및 한글 폴더·파일명 저장
- 실제 사이트(로그인 필요 사이트, 무한 스크롤, 대형 갤러리 500장 이상)에서의 판별 정확도와 속도
- "다운로드 전에 각 파일의 저장 위치 확인" 옵션이 켜진 Chrome에서의 동작
- 수십 MB 이상 이미지의 Referer 우회 다운로드 (data URL을 거쳐 저장하므로 메모리 사용량이 큼)
